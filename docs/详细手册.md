# 山海寻灵 · 防AFK控制器 v1.0

Windows 后台防 AFK 按键工具：自定义间隔、自定义按键、后台/最小化运行、多应用多窗口同时控制。

---

## 1. 启动方式

**双击 `启动.bat`** —— 就这一步。

它会自动：检查权限 → 弹 UAC 提权 → 找到可用的 Python → 启动界面。
点 UAC 弹窗的「是」即可。

![管理员模式](artifacts/gui_admin_mode.png)

右上角应显示 `🔓 管理员`。**如果显示 `🔒 普通权限`，说明没提权成功**，
这时游戏平台进程（High 完整性）打不进去，点旁边的「以管理员重启」。

### 其它入口

| 脚本 | 用途 |
|---|---|
| `启动.bat` | **推荐**。自动提权 + 自动找 Python |
| `run_admin.bat` | 手动提权启动（等价，但依赖 PATH 里的 python） |
| `run.bat` | 以当前权限启动，不提权。仅用于测试 Medium 目标 |
| `python main.py` | 直接跑（需自己保证是管理员） |

### 关于 Python 环境

`启动.bat` 通过 [scripts/find_python.bat](scripts/find_python.bat) 查找解释器，
按以下优先级：环境变量 `HELMD_PYTHON` → 常见安装路径 → PATH 中的 python
（**排除微软商店的 0 字节占位程序**）→ `py` 启动器。

找不到时会明确提示去 python.org 安装，不会卡住或闪退。

> **已知坑**：`C:\Users\<你>\AppData\Local\Microsoft\WindowsApps\python.exe` 是
> 0 字节的商店占位程序。如果 PATH 里它排在前面，直接写 `python main.py` 会弹出
> "去商店安装 Python"。启动脚本已专门排除它。

### 打包成 exe（可选）

```
scripts\build.bat
```
产物 `dist\山海寻灵防AFK.exe`，manifest 已声明 `highestAvailable`，
双击即自动请求管理员权限。需要先 `pip install pyinstaller`。

## 1.5 要不要管理员启动？—— 需要，已实测确认

**结论：需要。** 而且是硬性要求，不是优化项。

Windows 的 **UIPI（用户界面特权隔离）** 规定：低完整性（IL）进程不能向高完整性进程
发送窗口消息或 `SendInput`。`PostMessage` 会直接返回 `FALSE`，`GetLastError()==5`
（`ERROR_ACCESS_DENIED`）。

游戏平台（WeGame / TASLogin / 游戏本体）一般以管理员身份启动，因此是 **High 完整性**。

在本机实测（2026-11-18，Python 3.12 Medium 权限）：

| 目标进程 | 完整性 | 普通权限 | 管理员权限 |
|---|---|---|---|
| SpeedBall.exe | High | `FALSE` err=5 ❌ | `TRUE` err=0 ✅ |
| wegame.exe | High | `FALSE` err=5 ❌ | `TRUE` err=0 ✅ |
| tcls_core.exe | High | `FALSE` err=5 ❌ | `TRUE` err=0 ✅ |
| wegame_env.exe | High | `FALSE` err=5 ❌ | `TRUE` err=0 ✅ |
| SEGameTool.exe | High | `FALSE` err=5 ❌ | `TRUE` err=0 ✅ |
| explorer.exe | Medium | `TRUE` err=0 ✅ | `TRUE` err=0 ✅ |

**普通权限 0/5 → 管理员权限 5/5。** 全机统计：64 个带窗口进程中有 22~28 个是 High，
其中含游戏平台进程。

自己验证：
```
python main.py --permissions    # 列出本机所有需管理员才能控制的目标
python tests\test_uipi.py       # A/B 对照，打印 API 返回值与错误码
```

**怎么判断你的目标要不要管理员**：`python main.py --permissions` 里如果出现你的
游戏进程名，就需要。或者看界面日志——接管窗口时会自动做权限预检，权限不足直接
标红 `⚠ 权限不足` 并提示重启。

> **注意**：如果没有管理员权限，这类目标在界面上仍会显示"在线"，
> 因为消息确实投递出去了——只是被 UIPI 在内核层拦下。所以一定要看日志里的红色告警，
> 别只看"在线"两个字。

## 2. 三步上手

1. **＋新建任务** → 在「选择程序」下拉框里**直接选**正在运行的程序（无需手输进程名）
2. 设置 **按键**（默认 space）、**间隔(秒)**
3. 点 **▶ 启动 (F9)**

> **注意**：点「启动」时会自动应用表单里已填的内容，**不点保存也能跑**。
> 但想让它记住，还需要点一次「保存」。

### 完整操作流程（含删除）

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 点 **＋新建任务** | 左侧列表新增一行 |
| 2 | **在左侧列表点选这一行** | 必须先选中，右侧表单才会载入它 |
| 3 | 「选择程序」下拉框选目标 | 选中即自动填进程名 |
| 4 | 填「按键」「间隔(秒)」 | 间隔最小 0.5 秒 |
| 5 | 看底部 **「匹配 N 个窗口」** | **必须是绿色且 N ≥ 1**，0 就先别启动 |
| 6 | 点 **保存** | 落盘，下次启动还在 |
| 7 | 点 **▶ 启动 (F9)** | 开始工作 |
| 8 | 关窗口 / 最小化 | 收进托盘，后台继续 |

### 删除某一个任务

1. **在左侧「任务配置」列表里点选要删的那一行**
2. 点下方 **「删除」** 按钮
3. 确认框里看清楚地显示的是哪条任务（含匹配规则），点「是」

删除后：
- 该任务控制的窗口**立即脱管**，不再按键
- 其它任务**完全不受影响**，继续正常运行
- 配置立即保存到 `config/targets.json`

> 如果想临时停某个任务但不想删，取消勾选「启用本任务」再点保存即可。

### 修改已保存的任务

点选该行 → 改参数 → 点「保存」。运行中改也立即生效，不用重启。

### 点启动没反应？按这个顺序查

| 现象 | 原因 | 处理 |
|---|---|---|
| 日志提示"没有匹配到任何窗口" | 程序没开，或选错了程序 | 先启动游戏，再点「刷新」重新选 |
| 「匹配 0 个窗口」是红色 | 标题+进程名组合太窄 | 清空「窗口标题含」，只按进程名匹配 |
| 显示"在线"但游戏没反应 | 权限不足被 UIPI 拦截 | 看日志红色告警，以管理员重启 |
| 完全没反应也没有日志 | 没选中任务 | 先在左侧列表点选一行 |

## 2.5 程序下拉框怎么用

![界面](artifacts/gui_final.png)

- **下拉框会自动列出当前所有正在运行的程序**，按窗口数排序，多开程序带 `[N个窗口]` 标记
- 选中后自动填好进程名；任务名为空时还会自动命名
- 支持**输入过滤**：敲 `game` 就只剩含 game 的项
- 每 5 秒自动刷新，新开的游戏会自动出现；也可点「刷新」立即更新
- 右边的「匹配 N 个窗口」实时显示这条规则会接管几个窗口，**看到 0 就先别启动**

**多开怎么办**：选一个多开程序（如 `[3个窗口] 山海寻灵`）后，程序会自动提取
这些窗口标题的公共部分（如 `山海寻灵`）填入「窗口标题含」，把范围精确收窄到
那 3 个窗口，不会误伤同进程的其它窗口。

> **重要**：标题 + 进程名是 **AND** 关系（两个都填就必须同时满足）。
> 这样才能在 `python.exe`、模拟器这类宿主进程下精确锁定目标。

窗口标题或进程名任一命中即接管。同一进程开 3 个号，会自动接管 3 个窗口，各自独立计时。

## 3. 注入方式怎么选

| 方式 | 目标是否需在前台 | 能否最小化 | 适用 |
|---|---|---|---|
| `message` | **不需要** | **可以** | 模拟器（雷电/MuMu/蓝叠）、普通窗口程序 |
| `sendinput` | 需要（会自动闪切前台） | 可以，但会抢焦点 | 只认真实键盘的 DirectInput/RawInput 游戏 |
| `focus` | 自动闪切前台再闪回 | 可以 | 同上，每次约 120ms 抢焦点 |
| `both`（默认） | 不需要 | **可以** | 先用 message；目标恰好在前台时叠加 sendinput |

**判断方法**：默认 `both` 用两天，若游戏内 AFK 仍在掉，说明该游戏走 DirectInput 会丢弃 PostMessage，改用 `focus`。

## 4. 参数说明

| 参数 | 含义 |
|---|---|
| **选择程序** | **从下拉框选正在运行的程序**，选中即自动填进程名。可输入过滤 |
| 窗口标题含 | 标题子串匹配，大小写不敏感。多开时自动填入公共前缀 |
| 进程名含 | 如 `Game.exe` 或 `Game`（可省略 .exe）。选程序后自动填 |
| 按键 | `space` `enter` `tab` `esc` `f1`~`f24` `a`~`z` `0`~`9` `numpad0`~`numpad9` `left` `up` 等，或 `0x20` 直接写 VK 码 |
| 间隔(秒) | 最小 0.5 秒 |
| 抖动±% | 每次间隔随机浮动，避免固定节拍。5 表示 300s ±15s |
| 按下保持ms | 一个按键从按下到抬起的时长，默认 40ms |
| 自动接管全部匹配窗口 | 关掉则只控制第一个命中的窗口 |
| 单任务热键 | 独立启用/暂停该任务 |

## 5.5 关闭窗口 → 收进托盘（后台继续跑）

**点右上角 X 不会退出程序**，而是把窗口收进右下角托盘，引擎继续在后台工作。

默认勾选顶部 **「关闭时最小化到托盘」**。取消勾选后，点 X 会弹确认框再退出。

### 托盘图标能做什么

**双击 / 左键单击** → 恢复主窗口

**右键菜单**：

| 菜单项 | 功能 |
|---|---|
| 打开主窗口 | 恢复界面 |
| 启动 / 暂停 (F9) | 不切回窗口也能控制引擎 |
| 全部停止 (F10) | 立即停全部任务 |
| 当前接管 N 个窗口 | 状态显示（灰色只读） |
| 退出程序 | **真正退出** |

鼠标悬停图标会显示 `山海寻灵 · 防AFK控制器 · 运行中 · 接管3窗口`。

### 真退出只有两个途径

1. 托盘图标右键 → **退出程序**
2. 取消勾选「关闭时最小化到托盘」后点 X，并在确认框点「是」

> 实现说明：托盘用 Windows 原生 `Shell_NotifyIcon`（[app/tray.py](app/tray.py)），
> 不依赖 pystray 等第三方库，无需联网安装。图标为多尺寸 ico
> （16/32/48/64/128/256），托盘用 16px 版本。托盘消息循环跑在独立线程，
> 不阻塞界面。实测证据：窗口隐藏后引擎投递次数从 4 次继续增长到 9 次。

## 6. 行为特征

- **每个窗口独立计时**：3 个客户端 = 3 条计时线，互不阻塞
- **自动错峰**：新接管窗口按 0.2s 递推错开，不会同一毫秒齐发
- **智能窗口过滤**：只接管真正的主窗口。像 wegame 这类程序会创建十几个内部
  辅助窗口（`WECHAT_AUTH_MESSAGE_WIN` / `TCLS_CORE_WND` / `GDI+ Window` /
  `no_active_wnd` / `ClassName<数字>` …），全部排除，不会对着它们乱发按键
- **最小化仍生效**：过滤规则显式豁免最小化窗口（其客户区尺寸为 0x0，
  若按尺寸判断会被误杀）
- **自动重挂**：窗口关闭 → 20 秒宽限后丢弃；新窗口出现 → 3 秒内自动接管
- **连续失败脱管**：同一窗口连丢 5 次消息即停止尝试，日志标红，不会无限空打
- **权限预检**：接管时自动检查完整性级别，权限不足立刻标红告警
- **配置热保存**：存于 `config/targets.json`，原子写入（先写 .tmp 再 replace）

## 7. 常见问题

**Q: 游戏里没反应，但界面显示"在线"？**
界面显示的是"消息投递成功"，不代表游戏接收。游戏用 DirectInput/RawInput 会丢弃 PostMessage → 把注入方式改成 `focus`。

**Q: 全屏游戏无效？**
独占全屏下所有注入都受限。改成"无边框窗口"模式。

**Q: 显示"掉线"？**
窗口被关闭或连续 5 次投递失败。检查进程是否还在、是否被反作弊拦截。

**Q: 需要管理员权限吗？**
**需要。** 游戏平台进程多为 High 完整性，普通权限下 `PostMessage` 返回
`FALSE + err=5`（UIPI 拦截）。用 `run_admin.bat` 启动，或点界面右上角「以管理员重启」。
实测对照见 [1.5 节](#15-要不要管理员启动-需要已实测确认)。

**Q: 能同时控制几个应用？**
不限。每个"任务"可对应不同的 exe，多任务并行；同一任务内的多开窗口也全部接管。
